# LLM10 guided lab - Improper Output Handling

> **Difficulty:** Intermediate | **Time:** ~35 minutes | **OWASP mapping:** LLM05:2025 Improper Output Handling
> **Prerequisites:** LLM01 Prompt Injection, Basic SQL, HTML escaping

> Proposed by OWASP Siliguri; not an official OWASP project. Run this lab only against the
> local training application.

## Why this matters

Three features pass model output straight into downstream systems: a review summariser renders HTML, a product assistant builds SQL, and an order bot executes JSON actions. Attackers influence what the model writes, so each downstream system becomes injectable. Model output must be treated like any untrusted input.

**Threat:** Model output reaches a browser, database or business logic without validation or encoding.

**Impact if exploited:** Cross-site scripting, data exfiltration through SQL injection, privilege escalation and unauthorised actions.

## Learning objectives

- Explain why LLM output is untrusted input for every downstream interpreter
- Exploit HTML injection, SQL injection and unsafe structured-output execution
- Apply output encoding, parameterized queries and schema validation
- Fix a vulnerable query function and pass automated injection tests

Use the SQL path to read the admin api_token from the users table, then submit the FLAG{...} value.

## Fix it (Advanced mode)

**Parameterize model-generated SQL input** - The model extracts a category filter from the user's request; search_products() pastes it into SQL. Use a parameterized query so the filter is always treated as data. Return a list of rows.

Open the **Validate** tab in Advanced mode, edit `search_products()` and submit. Your code
runs in a resource-limited sandbox against deterministic attack tests: it must stop every
attack and still behave correctly for benign input.

## Mitigations to apply

- Encode output for the context it enters (HTML, attribute, URL, SQL, shell)
- Use parameterized queries; never concatenate model output into SQL
- Validate structured output against a strict schema and allow-list of actions and bounds
- Apply least privilege to every system the model output can reach

Treat every model output as untrusted: encode for HTML, parameterize SQL, validate structured output with a strict schema, and restrict what downstream handlers can do regardless of what the model asks for.
